# TimeKernel v2 要件定義書

## 概要

v1の基盤（カレンダー・予定管理・共有・時間割・バイト計算・MCP・Apple Watch）に加え、
v2では **オフライン対応・ウィジェット・通知・外部カレンダー連携** に加え、
競合調査から得られた **UX強化機能（ドラッグ&ドロップ、自然言語入力、空き時間可視化、投票調整、課題管理、ポモドーロ等）** 、
および **音声アシスタント連携（Alexa / Siri / Google Assistant）** を追加する。

> **優先度方針**: 競合カレンダーアプリ調査の結果、外部カレンダー連携（ユーザー継続率の鍵）と課題管理（学生特化の差別化）を前倒しし、Apple Watch・iPad対応はコア体験完成後に実施する。

---

## 1. オフライン対応

### 目的
ネットワーク接続がなくても予定の閲覧・追加ができるようにする。

### 仕様

| 項目 | 内容 |
|------|------|
| キャッシュ方式 | Firestore のオフラインパーシステンス（`enablePersistentCacheIndexAutoCreation`）+ AsyncStorage 補助 |
| オフライン時の閲覧 | キャッシュ済みデータを表示 |
| オフライン時の書き込み | ローカルに保存、オンライン復帰時に Firestore が自動同期 |
| 競合解決 | Firestore のサーバータイムスタンプ優先（last-write-wins） |
| 同期状態表示 | ヘッダーに接続状態インジケーター（オンライン / オフライン / 同期中） |

### 技術方針

- `firebase.firestore().enablePersistence()` を有効化（React Native Firestore のオフラインサポート）
- `NetInfo`（`@react-native-community/netinfo`）でネットワーク状態を監視
- オフライン状態のUI表示（バナーまたはアイコン）
- 未同期の変更にはインジケーターを付与（「同期待ち」マーク）

### データフロー

```
[ユーザー操作] → [ローカルキャッシュに書き込み] → [UIに即座に反映]
                                                    ↓
                                         [オンライン復帰時]
                                                    ↓
                                         [Firestoreに自動同期]
                                                    ↓
                                         [同期完了マーク表示]
```

## 2. ウィジェット（iOS / Android）

### 目的
ホーム画面から今日の予定やバイト情報をひと目で確認できるようにする。

### ウィジェット種類

| ウィジェット | サイズ | 表示内容 |
|-------------|--------|---------|
| 今日の予定 | Small / Medium | 今日の予定一覧（最大3〜5件） |
| 次の予定 | Small | 次に控えている予定（タイトル・時刻・残り時間） |
| 今月のバイト代 | Small | 今月の合計勤務時間 + 見込み給料 |
| 週間カレンダー | Medium | 今週の予定を簡易表示 |

### 技術方針

| プラットフォーム | 技術 |
|-----------------|------|
| iOS | `expo-widgets`（WidgetKit / SwiftUI） |
| Android | `expo-widgets`（Glance / Jetpack Compose） |
| データ連携 | SharedGroupPreferences（iOS）/ SharedPreferences（Android）経由でアプリからウィジェットにデータを渡す |

### ウィジェット更新タイミング

- アプリフォアグラウンド復帰時
- 予定の追加・編集・削除時
- タイムラインベースの定期更新（15分〜1時間間隔）

## 3. 通知・リマインダー

### 目的
予定の前にプッシュ通知でリマインドし、忘れ防止する。

### 通知種類

| 通知タイプ | トリガー | デフォルト |
|-----------|---------|-----------|
| 予定リマインダー | 予定開始の N 分前 | 15分前 |
| バイト開始通知 | シフト開始の N 分前 | 30分前 |
| 授業リマインダー | 授業開始の N 分前 | 10分前 |
| 共有カレンダー更新 | メンバーが予定を追加/変更した時 | ON |

### ユーザー設定

- 通知のON/OFF（全体 + タイプ別）
- リマインド時間の変更（5分前 / 10分前 / 15分前 / 30分前 / 1時間前）
- 共有カレンダー通知のON/OFF（カレンダーごと）
- おやすみ時間帯の設定（例: 23:00〜7:00 は通知しない）

### 技術方針

| 項目 | 技術 |
|------|------|
| ローカル通知 | `expo-notifications`（スケジュール通知） |
| リモート通知 | Firebase Cloud Messaging (FCM) |
| 共有更新通知 | Firestore トリガー → Cloud Functions → FCM |

### データ構造（追加）

```
users/{uid}/settings/
  └── notifications/
        ├── enabled: true
        ├── eventReminder: 15        // 分
        ├── shiftReminder: 30        // 分
        ├── classReminder: 10        // 分
        ├── sharedUpdates: true
        ├── quietHoursEnabled: false
        ├── quietHoursStart: "23:00"
        └── quietHoursEnd: "07:00"

users/{uid}/
  └── fcmTokens: ["token1", "token2"]  // デバイスごとのFCMトークン
```

## 4. 外部カレンダー連携（双方向同期）

### 目的
Google Calendar / Apple Calendar / Outlook など既存のカレンダーとTimeKernelを双方向同期し、ひとつのアプリで全予定を管理できるようにする。

### 対応サービス

| サービス | 方式 | 優先度 |
|---------|------|--------|
| Google Calendar | Google Calendar API（OAuth 2.0） | 高 |
| Apple Calendar | EventKit（デバイスローカル） | 高 |
| Outlook | Microsoft Graph API（OAuth 2.0） | 中 |
| iCal形式（汎用） | .ics インポート / エクスポート | 中 |

### 同期仕様

| 項目 | 仕様 |
|------|------|
| 同期方向 | 双方向（TimeKernel ↔ 外部） |
| 同期頻度 | 手動 + バックグラウンド定期同期（15分間隔） |
| 競合解決 | 最終更新タイムスタンプ優先 + ユーザー確認ダイアログ（重要な競合時） |
| 同期範囲 | 過去1ヶ月〜未来3ヶ月（設定可能） |
| マッピング | 外部予定 → TimeKernelの「event」タイプとして表示 |

### 機能詳細

#### インポート（外部 → TimeKernel）
- 外部カレンダーの予定をTimeKernelに表示
- 外部カレンダーの予定は視覚的に区別（アイコン or バッジ）
- インポート元ごとにカラー設定可能

#### エクスポート（TimeKernel → 外部）
- TimeKernelの予定を外部カレンダーに反映
- エクスポート対象のカレンダーを選択可能
- 予定タイプ（授業 / 予定 / バイト）ごとにエクスポートON/OFF

#### iCal対応
- .ics ファイルのインポート（ファイル選択 or URL指定）
- .ics ファイルのエクスポート（共有シートから送信）
- iCal URL購読（定期的にフェッチして同期）

### 技術方針

| 項目 | 技術 |
|------|------|
| Google Calendar | `expo-auth-session`（OAuth）+ Google Calendar API v3 |
| Apple Calendar | `expo-calendar`（EventKit ラッパー） |
| Outlook | `expo-auth-session`（OAuth）+ Microsoft Graph API |
| iCal | `ical.js` ライブラリでパース / 生成 |
| バックグラウンド同期 | `expo-background-fetch` + `expo-task-manager` |

### データ構造（追加）

```
users/{uid}/
  └── externalCalendars/
        └── {externalCalId}/
              ├── provider: "google" | "apple" | "outlook" | "ical"
              ├── name: "Google - 個人"
              ├── color: "#4285F4"
              ├── syncEnabled: true
              ├── syncDirection: "both" | "import" | "export"
              ├── lastSynced: timestamp
              ├── accessToken: "..."         // Google/Outlook（暗号化保存）
              ├── refreshToken: "..."        // Google/Outlook（暗号化保存）
              ├── icalUrl: "https://..."     // iCal URL購読用
              └── exportTypes: ["class", "event", "shift"]  // エクスポート対象タイプ

users/{uid}/
  └── externalEventMap/                     // 外部ID ↔ TimeKernel ID のマッピング
        └── {mappingId}/
              ├── externalId: "google_event_123"
              ├── internalEventId: "eventId1"
              ├── calendarId: "calendarId1"
              ├── provider: "google"
              └── lastSynced: timestamp
```

### 画面

| 画面 | 概要 |
|------|------|
| 外部カレンダー設定 | 連携先一覧、追加、削除、同期設定 |
| 連携先追加 | サービス選択 → OAuth認証 → カレンダー選択 |
| 同期状態 | 最終同期日時、同期エラー表示 |
| iCalインポート | ファイル選択 or URL入力 |

## 5. Apple Watch 拡張（v2）

### 目的
v1のApple Watch機能（予定表示・追加・バイト代表示）に、通知連携とオフライン対応を追加する。

### 5-1. Watch通知連携

| 項目 | 仕様 |
|------|------|
| 予定リマインダー | iPhone側の通知がWatchにも配信（標準UNNotification連携） |
| 触覚フィードバック | 通知時にHapticでユーザーに知らせる |
| 通知アクション | Watch上で「5分後にリマインド」「確認済み」を選択可能 |
| 共有カレンダー更新 | メンバーの予定追加/変更通知をWatch上でも受信 |

#### 技術方針
- iOSの通知はデフォルトでApple Watchに転送される（UNNotification）
- Watch側でカスタム通知UI（`WKNotificationScene`）を実装し、予定詳細を表示
- アクションボタン（スヌーズ / 確認）は `UNNotificationAction` で定義

### 5-2. Watchオフライン対応

| 項目 | 仕様 |
|------|------|
| キャッシュ範囲 | 今日〜3日分の予定 + 今月のバイト集計 |
| キャッシュ方式 | `WatchConnectivity` でiPhoneからデータ転送 → Watch側の `UserDefaults` / Core Data に保存 |
| 更新タイミング | アプリ起動時 + バックグラウンド転送（`transferUserInfo`） |
| iPhone未接続時 | キャッシュ済みデータを表示（「最終更新: ○時間前」を表示） |

#### 技術方針
- `expo-watch-connectivity`（v1で使用済み）を拡張
- iPhone側: 予定変更時に `WCSession.transferUserInfo()` でWatchにプッシュ
- Watch側: 受信データを `UserDefaults` に保存、アプリ起動時に読み込み
- 通信不可時は最終キャッシュデータで表示、古さインジケーター付き

## 6. ドラッグ&ドロップ（予定の移動・コピー）

### 目的
モバイルで直感的に予定を別の日時に移動・コピーできるようにする。主要カレンダーアプリでもモバイル未対応が多く、差別化ポイントとなる。

### 仕様

| 操作 | 動作 |
|------|------|
| 長押し → ドラッグ | 予定を別の日付/時間帯に移動 |
| 長押し → ドラッグ + コピーモード | 予定を複製して別の日付に配置 |
| 週表示での時間変更 | 上下ドラッグで開始/終了時刻を変更 |
| 月表示での日付変更 | 日付セル間のドラッグで日付移動 |

### UX詳細

- **ドラッグ開始**: 長押し（300ms）でHapticフィードバック + 予定がフローティング表示
- **コピーモード**: ドラッグ中に画面上部の「コピー」ゾーンにスワイプで切替、またはドラッグ前の長押しメニューから「コピーして移動」を選択
- **ドロップ先プレビュー**: ドラッグ中にドロップ先の日時をハイライト表示
- **キャンセル**: 元の位置に戻すとキャンセル
- **共有カレンダー**: 自分が作成した予定のみドラッグ可能（編集権限に準拠）

### 技術方針

- `react-native-gesture-handler` の `PanGesture` + `LongPressGesture` を組み合わせ
- `react-native-reanimated` でスムーズなドラッグアニメーション
- ドロップ時に `eventService.updateEvent()` を呼び出し（移動）または `eventService.addEvent()` を呼び出し（コピー）

## 7. 自然言語入力

### 目的
「来週火曜14時に歯医者」のようなテキスト入力だけで予定を自動作成する。MCP（AI連携）との親和性も高い。

### 仕様

| 項目 | 内容 |
|------|------|
| 入力場所 | カレンダー画面上部のクイック入力バー |
| パース対象 | 日付・時刻・タイトル・予定タイプ・場所 |
| 言語 | 日本語 / 英語 |
| 曖昧表現対応 | 「来週」「明後日」「今度の金曜」「再来週の月曜」 |
| 確認フロー | パース結果をプレビュー表示 → ユーザーが確認/修正 → 保存 |

### パース例

| 入力 | パース結果 |
|------|-----------|
| 「来週火曜14時に歯医者」 | 日付: 来週火曜, 時刻: 14:00, タイトル: 歯医者 |
| 「金曜18時からバイト 5時間」 | 日付: 今週金曜, 時刻: 18:00-23:00, タイプ: shift |
| 「明日の3限 経済学」 | 日付: 明日, 時限: 3限（時限設定から時刻解決）, タイプ: class |

### 技術方針

- `chrono-node`（日付パースライブラリ）+ カスタム日本語パーサー
- 予定タイプの自動判定: キーワードベース（「バイト」「シフト」→ shift、科目名パターン → class）
- 時限表現（「3限」）はユーザーの時限カスタム設定から時刻を解決
- MCP経由のAI入力も同じパースパイプラインを使用

## 8. 空き時間の自動可視化

### 目的
共有カレンダーのメンバー全員が空いている時間帯をワンタップで表示し、予定調整を効率化する。

### 仕様

| 項目 | 内容 |
|------|------|
| 表示方式 | カレンダーの週表示/日表示上に「全員空き」の時間帯をハイライト |
| 対象メンバー | 選択したカレンダーの全メンバー（個別ON/OFF可能） |
| 対象範囲 | 指定した日付範囲（デフォルト: 今週〜来週） |
| 営業時間フィルタ | 8:00〜22:00 のみ表示（ユーザー設定可能） |
| 空き時間からの予定作成 | 空き時間帯タップ → 予定追加画面に日時プリセット |

### UX詳細

- カレンダー画面のトグルボタンで「空き時間表示」ON/OFF
- 空き時間は緑色の半透明オーバーレイで表示
- メンバーが多い場合は「N人中M人が空き」のグラデーション表示
- 公開設定の時間割も空き時間計算に含める

### 技術方針

- 各メンバーの予定を Firestore から取得（`onSnapshot` でリアルタイム）
- クライアント側で時間帯の重なり計算（`useFreeSlots` カスタムフック）
- MCP の `get_free_slots` ツールと同じロジックを共有

## 9. 投票型スケジュール調整

### 目的
グループで予定を決める際、候補日を提示して参加者が投票し、最適な日時を決定する。飲み会、ゼミ、サークル活動の調整に最適。

### 仕様

| 項目 | 内容 |
|------|------|
| 作成 | 幹事がイベント名 + 候補日時（複数）を設定 |
| 投票 | メンバーが各候補に「○（参加可能）/ △（微妙）/ ×（不可）」で回答 |
| 結果表示 | 候補日ごとの回答一覧 + 最適日のハイライト |
| 確定 | 幹事が最適日を選択 → 自動で共有カレンダーに予定追加 |
| 期限 | 投票の締切日時を設定可能 |
| リマインド | 未回答メンバーにリマインド通知 |

### データ構造（追加）

```
calendars/{calendarId}/
  └── polls/
        └── {pollId}/
              ├── title: "ゼミ打ち上げ"
              ├── createdBy: "uid1"
              ├── createdAt: timestamp
              ├── deadline: timestamp
              ├── status: "open" | "closed"
              ├── confirmedSlot: null | { date, startTime, endTime }
              ├── candidates: [
              │     { date: "2026-03-20", startTime: "18:00", endTime: "21:00" },
              │     { date: "2026-03-21", startTime: "19:00", endTime: "22:00" }
              │   ]
              └── votes/
                    └── {uid}/
                          └── responses: [
                                { candidateIndex: 0, answer: "ok" },
                                { candidateIndex: 1, answer: "maybe" }
                              ]
```

### 画面

| 画面 | 概要 |
|------|------|
| 投票作成 | イベント名、候補日時追加、締切設定 |
| 投票回答 | 候補一覧 + ○△× 選択 |
| 投票結果 | メンバーの回答一覧 + 最適日ハイライト |

### 技術方針

- Firestore のサブコレクション `polls` で管理
- リアルタイム集計（`onSnapshot` で投票状況をライブ更新）
- 通知連携: 新規投票作成時・締切前にプッシュ通知
- 確定後は `eventService.addEvent()` でカレンダーに自動追加

## 10. 課題・テスト管理

### 目的
授業ごとに課題・試験を紐づけて管理し、締切カウントダウンで提出忘れを防止する。学生特化の差別化機能。

### 仕様

| 項目 | 内容 |
|------|------|
| 紐づけ | 時間割の科目に課題・テストを登録 |
| 種類 | 課題（assignment）/ テスト（exam）/ レポート（report） |
| 締切 | 日時指定 + カウントダウン表示 |
| ステータス | 未着手 / 進行中 / 完了 |
| カレンダー表示 | 締切日にカレンダー上に表示（専用アイコン付き） |
| リマインド | 締切前に通知（1日前 / 3時間前 / 1時間前、設定可能） |

### データ構造（追加）

```
timetables/{uid}/{timetableId}/slots/{dayOfWeek}_{period}/
  └── tasks/
        └── {taskId}/
              ├── title: "レポート提出"
              ├── type: "assignment" | "exam" | "report"
              ├── description: "第3章まとめ 2000字"
              ├── deadline: timestamp
              ├── status: "todo" | "in_progress" | "done"
              ├── createdAt: timestamp
              └── reminderMinutes: [1440, 180, 60]  // 通知タイミング（分）
```

### 画面

| 画面 | 概要 |
|------|------|
| 課題一覧 | 科目横断の課題・テスト一覧（締切順ソート） |
| 課題追加/編集 | 科目選択、種類、締切、メモ入力 |
| 時間割 > 科目詳細 | 科目タップで紐づく課題・テスト一覧表示 |

## 11. ポモドーロタイマー

### 目的
勉強のタイムブロッキングと集中管理を内蔵タイマーで実現する。カレンダーとの連携で「何をいつ勉強したか」を自動記録。

### 仕様

| 項目 | 内容 |
|------|------|
| 基本サイクル | 25分作業 → 5分休憩（デフォルト、カスタム可能） |
| ロングブレイク | 4サイクル後に15分休憩（デフォルト） |
| 科目紐づけ | タイマー開始時に科目を選択（時間割から） |
| 自動記録 | 完了したポモドーロをカレンダーに「勉強」イベントとして記録 |
| 統計 | 今日/今週/今月の勉強時間を科目別に集計表示 |

### 画面

| 画面 | 概要 |
|------|------|
| タイマー | カウントダウン表示、開始/一時停止/リセット、科目選択 |
| 勉強統計 | 科目別・期間別の勉強時間グラフ |

### 技術方針

- `expo-notifications` でバックグラウンドタイマー通知
- 勉強記録は `events` コレクションに `type: "study"` として保存
- バイト集計と同様の集計ロジック（`useStudySummary` フック）

## 12. 柔軟な繰り返しパターン

### 目的
v1の基本繰り返し（毎週）に加え、隔週・月次・カスタムパターンに対応する。

### 対応パターン

| パターン | 例 |
|---------|-----|
| 毎日 | 毎日8:00にジョギング |
| 毎週 N曜日 | 毎週火・木にゼミ |
| 隔週 | 2週間ごとの月曜 |
| 毎月 N日 | 毎月25日（給料日） |
| 毎月第N X曜日 | 毎月第2火曜 |
| N日/週/月ごと | 3ヶ月ごとの定期検診 |
| カスタム | 繰り返し終了日 / 回数指定 |

### データ構造（追加）

```
events/{eventId}/
  └── recurrence: {
        ├── frequency: "daily" | "weekly" | "biweekly" | "monthly" | "custom"
        ├── interval: 1              // N日/週/月ごと
        ├── daysOfWeek: [1, 3]       // 月=0, 火=1, ... （weeklyの場合）
        ├── dayOfMonth: 25           // 毎月N日（monthlyの場合）
        ├── weekOfMonth: 2           // 第N週（monthly + dayOfWeekの場合）
        ├── endDate: "2026-07-31"    // 繰り返し終了日（null = 無期限）
        └── endCount: 10             // 繰り返し回数（null = 無期限）
      }
```

## 14. 月表示の見切れ対策

### 目的
月表示で1日に多くの予定がある場合、全件が表示しきれず見逃す問題を解決する（TimeTree等で頻出の不満）。

### 仕様

| 項目 | 内容 |
|------|------|
| 表示上限 | 月表示の各日セルに最大3件表示（デバイスサイズに応じて2〜4件に自動調整） |
| オーバーフロー表示 | 上限を超える予定がある日は「+N件」バッジを表示 |
| +Nタップ動作 | タップで当該日のアジェンダビュー（全予定リスト）をボトムシートで表示 |
| 予定の優先表示 | 終日予定 → 時刻の早い順で表示し、重要な予定が見切れにくくする |
| 日セルタップ | 日付セルの空白部分タップで日表示に切替 |

### 技術方針

- 月表示コンポーネントで `maxVisibleEvents` を画面高さから動的に計算
- オーバーフロー分は `BottomSheet`（`@gorhom/bottom-sheet`）でアジェンダ表示
- アジェンダビューは日表示コンポーネントを再利用

## 17. プライバシー強化

### 目的
共有カレンダーで個人の予定が見えすぎる問題を解決し、ユーザーが安心して使えるようにする。

### 仕様

| 項目 | 内容 |
|------|------|
| 予定の公開レベル | 各予定に「公開」「タイトルのみ」「非公開（予定ありのみ表示）」を設定 |
| デフォルト公開レベル | カレンダーごとに新規予定のデフォルト公開レベルを設定可能 |
| メンバー別可視性 | 特定メンバーにのみ詳細を公開する設定（将来拡張） |
| データ暗号化 | Firestoreのセキュリティルールで他ユーザーの非公開予定へのアクセスを制限 |
| 退会時データ削除 | アカウント削除時に全個人データを完全削除するフロー |

### データ構造（追加）

```
events/{eventId}/
  └── visibility: "public" | "title_only" | "private"
      // public: 全詳細を共有メンバーに公開
      // title_only: タイトルと時刻のみ表示、詳細は非公開
      // private: 「予定あり」とだけ表示

calendars/{calendarId}/
  └── defaultVisibility: "public" | "title_only" | "private"
```

### Firestoreセキュリティルール（追加）

```
match /events/{eventId} {
  allow read: if isOwner(resource.data.userId)
    || (isMember(resource.data.calendarId)
        && resource.data.visibility != "private")
    || (isMember(resource.data.calendarId)
        && resource.data.visibility == "private"
        // private: 時刻とcalendarIdのみ返す（Cloud Functions経由で制御）)
}
```

### 技術方針

- 非公開予定の詳細フィルタリングは Cloud Functions 経由で安全に実施
- クライアント側でも表示ロジックで `visibility` に応じた情報制限を実装
- アカウント削除は Cloud Functions で全サブコレクションを再帰削除

## 開発フェーズ（v2）

> **Phase再編成の根拠**: 競合カレンダーアプリ（Google Calendar、Fantastical、Notion Calendar、MyStudyLife等）のユーザーレビュー調査結果に基づき、以下の方針で優先度を見直した。
> - **外部カレンダー連携を前倒し**: Google Calendar/Fantasticalで「これがあるから使い続ける」とされるキラー機能。ユーザー獲得・離脱防止に直結
> - **課題管理・ポモドーロを前倒し**: MyStudyLife等の学生向けアプリで最も評価される差別化機能。TimeKernelの学生特化戦略の核

> - **Apple Watch・iPadを後回し**: 学生の主要デバイスはスマホ。ニッチ機能より先にコア体験を完成させる
